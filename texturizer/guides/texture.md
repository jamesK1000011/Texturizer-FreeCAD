# Surface textures (Texturizer, based on BumpMesh by CNC Kitchen)

The engine, the settings and the sidebar are BumpMesh's by Stefan Hermann (CNC Kitchen), ported to Python and credited. Setting names are BumpMesh's (`texture_settings` lists them).

- Name the faces that must not change first — mating faces, press-fits, threads, a face another part slides on — and say them back to the person.
- `texture_list` gives the library (ids, categories, credits); `texture_settings { body, texture }` gives BumpMesh's settings and, for the body, the predicted triangles and a suggested `refineLength`.

## The draft (what the sidebar shows)

There is one draft per window, shared by the sidebar, the gallery and these tools: each call moves the sidebar live and the preview follows.

1. `texture_draft { part }` — the body (or a Mesh, or a Textured object to texture again: its settings come back). Opens the sidebar. `reset: true` is BumpMesh's Reset to defaults; `project: "<file>.bumpmesh"` its Load Project (`mode` all or settings).
2. `texture_mask { mode, add }` — `exclude` keeps the faces plain, `include` textures only them (switching clears the layer's faces, as BumpMesh). `add_by` direction / box / surface from picked faces; `fill { faces, maxAngle }` (a Mesh part: `fill { triangles: [seed], maxAngle, erase }`); `paint { strokes: [[{point, normal, triangle}, ...]], size, hardness, type, mode, snap, erase }` is BumpMesh's Brush on the tessellation, one undo step a stroke (mode `precision`, the default, splits triangles under the rim and Hardness under 100 fades to it, so a small `size` with `hardness` 100 is a fine hard edge by surface position; `standard` paints whole triangles; `snap: "faces"` paints every CAD face the brush touches whole and keeps it by its face name, so it follows the part through CAD changes); `clear`.
3. `texture_set { texture, settings }` — e.g. `{ textureHeight: 0.5, scaleU: 5, mappingMode: "cubic" }`; `frame { rotation }` (BumpMesh's Rotate, Euler XYZ), `frame { direction: [x, y, z] }` (a Planar projection looks along it; Triplanar / Cubic: the frame's Z; what the 3D view's projection arrow sets, with `rotation` and `scaleU` / `scaleV` in settings for its dial and size knob) or `frame { face }` (Place on Face); `cylinder` autofit / reset / from_face; `stamp` on / off / `{ point, normal }`.
4. `texture_layer { action }` — add (a copy of the active layer, Include Only), remove, move, solo, visible, blend cover / add, up to 4.
5. `texture_preview` — the engine's preview in the 3D view (Draft 500 k, Fine 1.5 M): edge, triangles, time, the export's size. Look with `view_snapshot`. `suggest: true` is BumpMesh's Suggest values. `turntable: true` spins the view about the part's vertical axis (`false` stops it); `turntable: 45` turns it once by 45° for a render series (turn, `view_snapshot`, turn, ...).
6. Say back the texture, depth, tile and the plain faces, then `texture_apply` — a Textured Mesh object beside the body (the body is untouched). Applying the same draft again updates that object; `new: true` makes another; `bake: true` is Bake Textures: the result becomes the part, and with Mask just-baked faces on (`bakeMask`, the default) the fresh layer excludes what was just textured. Like PartDesign hiding the previous feature, the Body is hidden while its textured result is shown (`bodyHidden` in the answer; its flat faces would otherwise show through the texture, and faces left smooth are part of the result): hiding or deleting the result, or Undo, shows the Body again.
7. `texture_export { format: stl | 3mf | bumpmesh, path }` — the file (3MF and STL carry the credit); `bumpmesh` is BumpMesh's Save Project.

## Following the body, and Update

A Textured object made from the draft is linked to its body (`Source`) and stores the draft. When the body changes it textures the body again by itself: with FreeCAD's window in the background (`TextureState` reads `updating…` until the new mesh is in), without a window inside the recompute. Its masks follow the faces by FreeCAD's stable names or their surface; a mask that no longer fits is left out and reported (`mask needs re-pick`), and faces a later CAD step made stay smooth until `texture_apply { update: "<object>", include_new: true }`. `texture_apply { update: "<object>" }` runs it again at once and answers `state`, `maskReport` and `newFaces`.

A Textured object made in one call (`texture_apply { body, texture, ... }`, no draft) stores its arguments instead: when its body changes it is only marked `OutOfDate`, and `texture_apply { update: "<object>" }` runs the same arguments again. Its faces are names, so check them after a CAD change.

## Size, time and limits

- The engine refines the part's mesh until no edge is longer than `refineLength` (1 mm by default), displaces it, then reduces it to `maxTriangles` (750 000 by default). Halving `refineLength` makes about four times the triangles, the memory and the time.
- `texture_settings { body, texture, settings }` and `texture_preview` answer the estimate before anything runs (`subdividedTriangles`, `memoryBytes`; about 420 bytes per refined triangle). `texture_apply` and `texture_export` refuse a run estimated over `memoryLimitGB` (4, about 10 million refined triangles) and say what to raise; the engine also stops refining at its own cap and says so in `warnings`.
- `texture_apply` changes the document, so it cannot run as a job: it runs inside the call and FreeCAD's window is busy until it ends. `texture_preview`, `texture_export` and `texture_prepare` are long reads: past about 45 s the call answers with a job id and `job_status` gives the answer.
- On a large part, a mask (only the faces that need texture) costs far less than a finer `refineLength`: plain faces are kept as they are (`preserveUntextured`).
- `texture_export` without `path` (and without `ask: false`), `texture_draft { project: "ask" }`, `texture_set { texture: { upload: true } }`, `stamp: "place"`, `face: "selected"` and `add: "selected"` wait for a person at the window. Give paths, names and points instead.
- A path in `texture.file`, `mask`, `project` or `export.path` is checked as Agent Link checks `path`. A file in a credentials or settings folder is refused. A file name with hidden characters is refused: the person renames the file.
- Faces are `Face1`..`FaceN` of the part as it is now (from 1); triangles are indices from 0 of the part's tessellation at 0.02 mm (`texture_draft` answers the count). Both change when the CAD model changes.
- The result is a mesh beside the body, never a solid: fillets, holes and booleans do not build on it. Texture last. Then `slice_with` (Workshop for FreeCAD) takes the Textured object as it is; or export it (`texture_export`, or `texture_apply`'s `export`) and slice the file.

## Without the draft

- A cylinder along any axis, or a turned body, in one call: with mappingMode 3 (cylindrical) and no `rotation`, the axis is fitted to the cylindrical faces the call textures (the largest sets it; the ones parallel to it are named), as Auto-fit and `cylinder: "from_face"` do in the draft. The answer says so: `cylinder { axis, centre, radius, from }` and `frame { rotation, from }`. With other projections and no `rotation`, a body whose Placement is turned is textured in its own axes (`frame.from`: the body's Placement), so a planar or cubic texture turns with the part. Give `rotation` to choose the frame yourself. In the draft, `texture_draft { part }` on a new part fits the axis the same way when every layer maps cylindrically and no frame or cylinder is set.
- `texture_apply { body, texture, faces, mode, settings }` runs BumpMesh's engine in one call: `include` textures only the faces (a grip), `exclude` keeps them plain. Depth `textureHeight` (mm), tile `scaleU` (mm), `mappingMode` 0-8, up to 4 `layers`, each `{texture, settings, faces, mode}`: a layer that gives no `texture`, `faces` or `mode` takes the top-level one; one that gives a different one is refused. Settings go in `settings` (every layer) or the layer's `settings`. `export: "part.stl"` (or .3mf) writes the file too. It can be updated the same way.
- `texture_prepare { body, faces, mode }` writes the part as an STL and a mask of those faces' triangles, for texturing outside FreeCAD.

## Check

`texture_check { object }` — the Textured object `texture_apply` made, checked against its body with the mask it stores (no `texture_prepare` needed; `path` of its `texture_export` STL works too). For a file textured outside FreeCAD, `texture_check { body, path }` with `texture_prepare`'s mask. It answers the depth on each textured face, `leaked` (a face meant to stay plain that moved: fix the mask, texture again), `bare` (meant for texture, barely moved: the texture is finer than `refineLength`), and whether the mesh is closed. Only an `ok` goes to the slicer. A textured part is a mesh: slice it as it is — `slice_with { body: "<the Textured object>" }` (Workshop for FreeCAD) puts it on the plate with no new triangles, or slice the file `texture_export` wrote.

## texture_apply in full
<!-- later: when a texture_apply answer, an input or a refusal needs explaining -->
Everything texture_apply's tool card held before it was cut short. The card keeps the inputs, what it makes, the traps and the main keys of the answer.

**What it makes.** Texture a part and put the result in the document (Add to document / Update / Bake Textures). The engine is BumpMesh's (Stefan Hermann, CNC Kitchen), ported to Python and run inside FreeCAD. The result is a new Textured Mesh object beside the body. The body and its Shape are never changed. The result is a mesh, not a solid: later CAD steps (fillets, holes, booleans) do not build on it. So texture last. Then slice_with (Workshop for FreeCAD) takes the Textured object as it is, a mesh on the plate. Or export it (export here, or texture_export) and slice the file.

**The three ways to call it.** There are three ways to call it. (1) The draft: with no texture and no layers, it textures the draft that the sidebar shows. Use texture_draft, texture_set and texture_mask first. body switches the part of the draft; draft loads a whole draft first. It makes the object, or updates the one this draft made before. new: true makes another; name labels it. (2) In one call, no draft: body, texture (a library id, texture_list), and faces with mode. mode include textures only the faces (a grip). mode exclude (the default) keeps them plain; with no faces, everything is textured. settings: by BumpMesh's names (textureHeight mm deep, scaleU mm per tile, mappingMode 0-8 or a name, refineLength mm, maxTriangles). rotation: [x, y, z] degrees (BumpMesh's Rotate). Or give up to 4 layers, bottom first, each {texture, settings, faces, mode, blendAdd, visible}. A layer without its own texture, faces or mode takes the top-level one. A layer that differs from the top-level one is refused. The layer settings in settings are the defaults of every layer. (3) update: a Textured object's name, run again now with what it stores. include_new: true also textures the faces that a later CAD step made; they stay smooth until then. bake: true (draft only) is BumpMesh's Bake Textures. The undecimated result becomes the part of the draft, with a fresh layer. With bakeMask on (the default), that layer excludes what was just textured. export: a path ending .stl or .3mf (relative: the output folder), or {path, format}, writes the file as well.

**Following the body.** Following the body: an object made from the draft is linked to its body. It textures again by itself when the body changes. With the window, this runs in the background, and TextureState is "updating…" meanwhile. Its masks follow the faces by FreeCAD's stable names or their surface. A mask that no longer fits is left out and reported (maskReport), never guessed. An object made the one-call way (2) is only marked OutOfDate when its body changes: run update. Face names are Face1..FaceN of the body as it is now (from 1). They renumber after CAD changes, so read them again before a one-call apply.

**Size and cost.** Size and cost: this changes the document, so it cannot run as a job. It runs inside the call, and FreeCAD's window is busy until it ends. The mesh is refined until no edge is longer than refineLength (1 mm by default). Halving refineLength makes about four times the triangles and the time. The mesh is then reduced to maxTriangles (750 000 by default). A run estimated over memoryLimitGB (4, about 10 million refined triangles) is refused with what to raise. Ask texture_settings { body, texture, settings } or texture_preview for the estimate first. On a large part, prefer a mask (only the faces that need texture) to a finer refineLength. tolerance (one-call way only): the body's tessellation in mm (0.02).

**The answer.** The answer holds { body, object, label, updated, triangles, inputTriangles, repair, warnings, layers, engine, credit, export, next } and "health" from the shared check. object: the name of the Textured object. warnings: for example, the subdivision hit its cap, so the texture is coarser than asked; open edges. layers: each with layer, mode and faces; name and texture too when made from the draft. layer is its index from 0, bottom first: the number that texture_mask, texture_set and texture_layer take. engine { refineLength, maxTriangles, subdivided, displaced, output, ms per stage }; export { path, format, triangles }. After an update it also holds state / maskReport / newFaces / included. After a bake it also holds baked / maskedTriangles.

**The body hidden, the preview closed.** As PartDesign hides the previous feature, the Body is hidden while its textured result is shown. Its flat faces would show through; faces left smooth are part of the result mesh. bodyHidden true and the note say so. Hiding or deleting the result, or Edit > Undo of the apply, shows the Body again. If a preview showed, it is closed and switched off in the view of its own document. The next draft tool brings it back on the body.

**With FreeCAD's window.** With FreeCAD's window, the answer has window. window holds the document in front and the draft's (activeDocument, draftDocument, draftInFront), previewShowing and userHidden. It holds the preview's nodes in the active view's scene graph and whether each is on (preview.scene.previewNodes). It holds the eyes of the result and the body (result, source: visible, shown). resultInView says whether the camera sees the centre of the result's box. To tell why a view with the result shown still draws nothing, it holds four more keys. resultView: the result's DisplayMode, Visibility, Transparency, facets, its RootNode and SwitchNode. camera: type, position, nearDistance, farDistance, focalDistance, height. scene: the active view's scene graph two levels deep (each node's type, name, children and whichChild, style, transparency, on, test). viewer: the whole scene of the viewer, two levels.

**Refusals and after.** numpy can refuse a Texturizer bug: an array in a truth test, or a shape that does not fit. The call is then refused with code failed and the file:line it came from. It opens no dialog or progress window. Then texture_check { object } measures the result against the body.

## texture_set in full
<!-- later: when a texture_set input, a setting or a refusal needs explaining -->
Everything texture_set's tool card held before it was cut short. The card keeps the inputs, the traps and the answer.

**What it changes.** Change the draft (texture_draft first). It is a partial update in one undo step. The sidebar's controls move as it runs.

**layer, active and texture.** Inputs: layer (0 = bottom; the active one when left out). active: make this layer the one the sidebar edits; done first. texture: a library id (texture_list), or {"file": a PNG heightmap's path}. A PNG is copied into your custom textures. A file in a credentials or settings folder is refused. A file name with hidden or control characters is refused. A PNG over 8192 × 8192 pixels is refused. Setting a texture also resets scaleU / scaleV to the texture's tile scaled to the part. So give settings in the same call or after.

**settings.** settings: by BumpMesh's names (texture_settings lists them). Layer settings, for example: scaleU / scaleV (mm per tile; scaleV follows scaleU while lockScale is on). textureHeight (mm, the depth) is the same control as amplitude, taken unsigned. invertDisplacement: true cuts in instead of standing out. mappingMode: 0-8 or a name such as "cubic". rotation: degrees, in the surface. Run settings: refineLength (mm: the edge the mesh is refined to) and maxTriangles (the result is reduced to it). bottomAngleLimit / topAngleLimit (degrees): faces flatter than this, facing down / up, stay plain.

**frame, cylinder and stamp.** frame {rotation: [x, y, z] degrees} is BumpMesh's Rotate: it turns the texturing frame, not the body. frame {direction: [x, y, z]} points a planar projection along it; not [0, 0, 0]. frame {face: a face name or "selected"} is Place on Face. cylinder autofit | reset | from_face (with face: a cylindrical face's name) is for cylindrical mapping. stamp "on" | "off" | {point, normal} places one tile at a spot. stamp "place" uses a spot clicked in the window. A name that is not a setting is refused. An engine tuning setting that the draft does not hold is refused; those go in texture_apply's settings.

**A person at the window, and the answer.** {"upload": true} as texture, stamp "place" and face "selected" need a person at the window. The answer holds: layer, set and draft (as texture_draft). set holds what was set, with the values the draft took after clamping. The model is untouched: nothing is textured until texture_preview or texture_apply. The draft is kept in the document, so Edit > Undo undoes it.
